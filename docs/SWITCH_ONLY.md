# What is Switch-only and what is not

SwitchAirCast has two builds: `Makefile` (devkitPro, produces `SwitchAirCast.nro`) and
`Makefile.linux` (a desktop build for development and tests, see [DEVELOPING.md](DEVELOPING.md)).
The compile-time switch between them is `__SWITCH__`, which `Makefile` defines and
`Makefile.linux` does not. This page lists what depends on it, and the few other differences.

Both builds compile every `*.c` file in `source/`, `lib/airplay/` (with `playfair/`, `llhttp/`
and `mdnsd/`), `lib/plist/src` and `lib/plist/libcnary`. Neither build uses OpenSSL or Avahi:
crypto goes through mbedtls and libsodium, and the built-in mDNS responder in `lib/airplay/mdnsd/`
announces the service, in both. Only `Makefile.linux` builds `tests/`.

## Switch-only

Exists only for the Switch, or is used only by the Switch build.

| Path | What it is |
| --- | --- |
| `Makefile` | devkitPro and libnx rules; builds the `.nro` and `.nacp`. Links `-lnx`, `sdl2`, `SDL2_ttf`, FFmpeg, `mbedcrypto` and `libsodium` from the portlibs. Defines `__SWITCH__` and `SYS_ENDIAN_H`. Refuses to link the stock `switch-ffmpeg` unless `ALLOW_STOCK_FFMPEG=1`. |
| `tools/build-ffmpeg-switch.sh` | Cross-builds devkitPro's FFmpeg 7.1 for Horizon (`--target-os=horizon`, `--enable-libnx --enable-nvtegra`) into `build/ffmpeg-switch`, applying `patches/ffmpeg-*.patch`. |
| `patches/ffmpeg-nvtegra-h264-long-ref.patch` | Fixes `libavcodec/nvtegra_h264.c`, the NVDEC H.264 hardware decoder in devkitPro's FFmpeg. That file does not exist in stock FFmpeg. |
| `icon.jpg` | Homebrew menu icon, used by `Makefile`. Regenerated by `tests/make_icon.c`, which runs on the desktop. |
| `source/platform.c`, Switch half (`#ifdef __SWITCH__` at line 85 to the `#else` at line 333) | libnx services: sockets (`socketInitialize` with a larger buffer config), `nifm` (IP address), `set`/`setsys` (nickname, language, OLED model), `ssl` (HTTPS for FFmpeg), `pl` (system font), `lbl` (backlight), `hid` six-axis sensor (rotation), `applet` (applet mode, handheld mode, keep awake, focus changes), `nxlink` (log forwarding), `randomGet`. |

There is no `deko3d` code or dependency in the repository. Drawing goes through SDL2's renderer
(`source/main.c`, `source/ui.c`); the code does not show what SDL2 uses underneath on the Switch.

## Shared, with a Switch-specific branch

These files build everywhere, and a guard changes what they do on the Switch.

| Path | The guard and what it changes |
| --- | --- |
| `source/platform.c` | The Switch half above and a desktop half (line 333 to 489) implement the same `source/platform.h`. Desktop: data folder `~/.config/switchcast` (or `SWITCHCAST_DATA_DIR`), IP from the route to the mDNS group, `SWITCHCAST_OLED`, `SWITCHCAST_APPLET` and `SWITCHCAST_HANDHELD` environment variables stand in for the console state, a system DejaVu or Noto font, `getrandom`. No backlight, motion sensor or keep-awake. Logging and the log history are shared. |
| `source/video.c:109` and `source/video.c:174` | Only on the Switch: asks for the `AV_PIX_FMT_NVTEGRA` pixel format and creates an NVDEC (`AV_HWDEVICE_TYPE_NVTEGRA`) device when hardware decoding is allowed. The desktop build always decodes H.264 in software and ignores `allow_hw`. |
| `source/main.c:21`, `source/main.c:427` | Includes `switch.h`; opens a 1920x1080 fullscreen window on the Switch, a resizable 1280x720 one on the desktop. |
| `source/main.c:180` and `source/main.c:747` | Desktop only: `SWITCHCAST_SNAPSHOT` saves a BMP of the screen. |
| `lib/airplay/crypto.c:34`, `:64`, `:82`, `:94` | Random bytes: `randomGet` from libnx on the Switch (libsodium's default wants `/dev/urandom`, which Horizon lacks), libsodium's own generator elsewhere. The rest of the file is the same on both. |
| `lib/airplay/mdnsd/mdnsd.c:21`, `:354`, `:429`, `:537`, `:549` | On the Switch: no `ifaddrs.h`; the IPv4 address comes from `gethostid()`; no IPv6 address or socket; if joining the multicast group fails it keeps running and only announces. Elsewhere it uses `getifaddrs` (or the Windows adapter list), and closes the socket and returns an error if the group cannot be joined. |
| `lib/airplay/mdnsd/dnssd_mdnsd.c:66` | On the Switch the host name is `SwitchAirCast-` plus the last three bytes of the device id. Elsewhere it is the machine's host name (`UxPlay` if that is empty). |
| `lib/airplay/byteutils.c:40` | `SYS_ENDIAN_H` is defined only by `Makefile`; it selects `<sys/endian.h>` instead of `<endian.h>`. |

`Makefile.linux` also defines `HAVE_GMTIME_R` and `HAVE_LOCALTIME_R`, which `Makefile` does not;
libplist's `lib/plist/src/time64.c` supplies its own versions when they are missing. Each Makefile sets
`SWITCHCAST_VERSION` on its own (`APP_VERSION` in `Makefile`, a literal in `Makefile.linux`).

## Portable

No Switch dependency; also runs in the desktop build. Nothing in these files includes `switch.h`
or calls libnx; whatever they need from the console they get through `source/platform.h`.

- `source/audio.c`, `source/config.c`, `source/i18n.c`, `source/player.c`, `source/receiver.c`,
  `source/ui.c` (with the notes above).
- `lib/plist/` (libplist and libcnary).
- `lib/airplay/`, except for the guarded places listed above. This includes `srp.c` (mbedtls
  bignums), `playfair/`, `llhttp/`, the HTTP and RTSP handlers, the mirroring and audio RTP code,
  and the mDNS responder apart from its guards. The `_WIN32` and `__APPLE__` branches in this
  directory are not compiled by either Makefile.
- `tests/`: the `.c` programs are built only by `Makefile.linux` (`make -f Makefile.linux tests`),
  and the `.py` and `.sh` scripts drive those programs. `Makefile` builds none of them.

Some portable code still reads as Switch-shaped: `source/main.c` numbers the SDL joystick buttons
as the Switch reports them (the desktop build adds keyboard keys for the same actions), and the UI
texts in `source/i18n.c` talk about "this Switch".

## Changes to the vendored UxPlay library

The list of changes is in [DEVELOPING.md](DEVELOPING.md#changes-to-uxplays-library). Here is
each one by whether it depends on the Switch. The repository has a single commit that adds
`lib/airplay/`, so its history cannot show which lines differ from UxPlay's; this sorting is
from reading the code.

**Switch-specific** (guarded by `__SWITCH__`, or only needed there):

- `crypto.c` is a rewrite on mbedtls and libsodium because devkitPro has no OpenSSL. Only the
  random-number code is guarded (`crypto.c:34` onwards); the rest compiles and runs unchanged in
  the desktop build, and `tests/crypto_test.c` compares it with UxPlay's OpenSSL output.
- The mDNS changes under `__SWITCH__` in `mdnsd/mdnsd.c` and `mdnsd/dnssd_mdnsd.c`, listed in the
  table above: IPv4 only, address from libnx, per-console host name, announce-only fallback.

**Added because of the Switch, but not guarded** (they run in both builds):

- `srp.c` is an SRP-6a verifier on mbedtls bignums instead of OpenSSL. The Mac pairing code
  depends on it (`tests/srp_server.c`, `tests/srp_test.py`).
- `raop_hls_export_playlists()` in `raop.c` and `airplay_video_export_playlists()` in
  `airplay_video.c` hand the player the playlists the library would serve on
  `http://localhost:<port>`, so the Switch does not need loopback networking.
  `source/receiver.c` calls it in both builds.
- The re-announcement every 60 seconds (`MDNS_REANNOUNCE_INTERVAL` in `mdnsd/mdnsd.c`) has no
  guard either, so it also applies on the desktop.

**General fixes, not tied to the Switch** (plain C and POSIX, no guards):

- `mirror_buffer.c`: `mirror_buffer_decrypt` no longer writes past its output when a packet is
  shorter than the keystream left from the previous one (`tests/mirror_decrypt_test.c`).
- `raop_rtp_mirror.c`: empty mirroring packets are skipped, a payload size over 32 MB or negative
  ends the connection, and a failed allocation no longer calls `exit()`.
- `fairplay_playfair.c`: `fairplay_setup` rejects a mode byte above 3 and `fairplay_handshake`
  rejects `req[12]` above 3, which the original used as array indices.
- `threads.h`: `THREAD_JOIN` does nothing for a handle that is 0, and `THREAD_CREATE` sets the
  handle to 0 when `pthread_create` fails; `httpd.c` (`httpd_start`) returns an error when the
  thread could not be created, and the `raop_ntp`, `raop_rtp` and `raop_rtp_mirror` start
  functions log it.
- `raop_handlers.h`, `pair-setup-pin`: the client's proof, `epk` and `authTag` are length-checked
  before they are copied, and a missing session fails the step. `pair-pin-start` keeps the code
  for `PIN_REUSE_SECONDS` (120, in `raop_handlers.h`; the time is stored in `raop.c`), so repeated
  requests show the same code.
- `pairing.c`: `srp_new_user` and `srp_validate_proof` free what they allocate and check that the
  session has SRP state.
- `httpd.c:486` and `:541`: requests on the reverse (PTTH) channel are marked with
  `http_request_set_reverse()`; the original called the getter `http_request_is_reverse()`.
- `raop.c`: a changed `X-Apple-Session-ID` on an open connection logs a warning instead of
  tripping an `assert`.
- `raop.h`, `raop_handlers.h`: `display_pin` is called with an empty string when pairing finishes
  or fails, so the application can hide the code.
- `http_handlers.h`, `/play`: a request without `Content-Location` but with `host` and `path`
  (a local file sent by QuickTime) is turned into `http://host/path`, with checks on both fields.
  The application advertises feature bit 35 for it in `source/receiver.c`, not in the library.
